# Synthetic fixtures

These examples use project `demo` only. They do not represent actual tasks, approvals, files generated by an agent, or successful live verification.

`manifest.json` lists expected structural outcomes. All three report variants are independent alternative scenarios for the same contract, not a claim that contradictory observations occurred together. PASS/FAIL evidence IDs name hypothetical trusted receipts; UNKNOWN explicitly has no attempt manifest. The fixtures demonstrate the wire contract, not real evidence authenticity.

`capture.txt` is exact input bytes for intake digest verification. `contract.canonical.txt` is an ASCII canonicalization golden fixture; it omits the contract's digest field. Proposal digest covers assertion bytes, not the authorization binding. Runtime authorization/evidence-reference existence is outside these examples.

`report.aggregate.semantic-invalid.json` is structurally valid but semantically invalid: top-level PASS disagrees with its UNKNOWN required check. This distinction is intentional. Schema validity never proves completion.

The seven schemas are self-contained draft 2020-12 documents. The manifest covers nineteen structural fixtures, including evidence, proposal, revision and Memory migration examples. No external schema fetching is needed. Full metaschema validation is separately tracked in the validation report.
